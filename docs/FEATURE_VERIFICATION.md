# MOHIVX 1.2.0 — التحقق والحدود

تاريخ العمل: 2026-10-17. يحل هذا السجل محل تقارير المراحل السابقة. لا يعني نجاح البناء قبول كل الوظائف على جهاز فعلي.

## تغييرات هذا الإصدار

- خلفية الجزيرة سوداء معتمة دون بلور في الثيمات الداكنة؛ بطاقات محايدة وأزرق افتراضي مستمدان من لوحة Coucou. شريط مضيء للشكل الأصلي عند الطي.
- قياس محتوى كل قسم فعليًا ومراقبة تغيّر حجمه، بدل الارتفاعات الثابتة. تتبع نافذة Windows القياس النهائي والحركة، مع الحد بمساحة الشاشة. إضافة تطبيق أو فتح تفاصيل يزيد الارتفاع وإغلاقها يصغّره.
- صفحة الوكلاء على الكمبيوتر: جلسات حقيقية من الخطافات، حالات العمل والانتظار والانتهاء، وخطوات العمل وفروق الملفات باستخدام محرك Coucou الفعلي.
- وسيط Rust مقتبس من Coucou، مع تطبيع أحداث الوكلاء وعقود ردودهم، وأنبوب Windows محلي والتحقق من هوية خادمه ورمز اتصال. لا يُشغّل التطبيق أو الوسيط الأمر المعروض؛ يعيد الوسيط قرار الطلب إلى الوكيل الذي أرسله.
- ربط Claude Code وCodex وAntigravity وGemini CLI وCursor بعد مراجعة التغيير في الواجهة. يحافظ على الإعدادات والخطافات الأخرى، ويرفض الملفات التالفة والتغييرات التي تحدث بعد المراجعة، ويحفظ نسخة احتياطية.
- موافقات الخطافات المتوافقة لـClaude Code وCodex: معرّف وبصمة الطلب الكامل ووقت انتهاء واستهلاك مرة واحدة. الطلبات المبتورة أو الأكبر من حد المراجعة تعود إلى الوكيل الأصلي. Antigravity وGemini وCursor للمتابعة حاليًا.
- Android بثيم محايد وأزرق، وصفحة جلسات وتغييرات وطلبات موافقة. تتطلب القرارات صلاحية مستقلة من الكمبيوتر. السماح والإجابات يتطلبان تأكيد الهوية بالبصمة أو قفل الهاتف. يحافظ تحديث الحالة على موضع التمرير.
- الاقتران بالأرقام الستة والاكتشاف المحلي وتثبيت شهادة TLS محفوظة، وكذلك بقية وظائف MOHIVX.

## نتائج مؤكدة للإصدار 1.2.0

- **56 اختبار Node ناجحًا، بلا فشل أو تجاوز.** تشمل خدمات MOHIVX السابقة، واقتران HTTPS الفعلي بعميل Java، وسحب الصلاحيات وإعادة الإرسال، والروتين والتركيز والخلفيات والصوت، إضافة إلى الوسيط الجديد.
- شغّلت الاختبارات وسيط Rust الحقيقي عبر أنبوب معزول: أحداث جلسة، فرق Edit، السماح والرفض وعقد إجابة سؤال، ورفض الطلب الطويل. النصوص تجريبية ولم تُنفّذ أوامر لوكلاء المستخدم.
- تحقق مستقل من أن قراءة حالة الوكلاء لا تمنح الموافقات للهاتف، وأن القرار يحتاج البصمة المطابقة ويُرفض بعد استهلاكه أو سحب الجهاز.
- **30 اختبار Rust ناجحًا** لتطبيع الأحداث وحدود النصوص وصيغ ردود الوكلاء والإجابات. النسخة المحلية مبنية لـWindows x64؛ لا يُدّعى دعم Linux بهذا الدمج.
- اختبار Chromium بلا واجهة على **46 حالة تخطيط**: الأقسام التسعة × الأشكال الخمسة، وقائمة طويلة على شاشة صغيرة. تحقق أيضًا من ثبات الخلفية السوداء مع الثيمات، والنمو والتقلص، وفروق الملفات، وتمرير هوية الطلب وبصمته، والإجابات، وتعطيل الطلب المنتهي، ومراجعة الربط قبل تفعيله.
- نجح بناء TypeScript وVite ووسيط Rust. بُني APK 1.2.0 من المصدر باسم MOHIVX وأيقونة الشعلة الزرقاء، مع إضافة إذن البصمة.
- طابق فحص التغليف **42 ملفًا** من خدمات Electron والوسيط والتراخيص وواجهة JavaScript/CSS مع المصدر. نجح تشغيل HTTPS من الأرشيف وحفظ المفتاح مشفرًا وإعادة فتحه ورفض طلب بلا ربط برمز 401. نجح أيضًا نقل حدث Edit عبر الوسيط المجمّع إلى محرك الفروق من الأرشيف، دون فتح نافذة أو تنفيذ الأمر التجريبي. اجتاز APK فحص التوقيع v2، ونسخته 1.2.0 وشهادته هي شهادة التجربة السابقة نفسها.

## قبول سابق محفوظ

اختُبر APK **1.1.2** على Samsung A21s عبر Wi-Fi فعليًا: اكتشاف، رمز من ستة أرقام يبدأ بصفر، بيانات RAM ومدة التشغيل، ثم سحب الربط والعودة لشاشة الاقتران. سبق أيضًا اختبار تغيير خلفية Windows بالسهم وقراءة المسار الكامل، واختبار الصوت بإذن مؤقت واستعادته. لا تعني هذه النتائج قبول واجهة أو بصمة الإصدار الجديد.

اجتاز Hermes المثبت فحص ACP وإنشاء جلسة فعلية في مرحلة سابقة دون إرسال طلب نموذج مدفوع.

## حدود التحقق

- بناء 1.2.0 واختباراته تمت في الخلفية احترامًا لطلب المستخدم عدم استخدام الجهاز. لم تُفتح نوافذ التطبيق أو تُغيّر إعدادات الوكلاء الحاليين، ولم يُثبّت APK الجديد على الهاتف. قبول الحركة وDPI والبصمة على الجهاز الفعلي ما زال مطلوبًا.
- كود Coucou مدمج للوظائف المذكورة فقط. لم تُنقل شخصية Mochi أو أصولها أو جميع ميزات Flow والتدوين والإضافات. يحفظ المشروع تراخيص MIT ونسب الكود إلى Louis Raillé وRhytam Biswas، عند المراجعة `434d6a2b4af2e5ce117fa425170abe25620130b9`.
- وصول أحداث الوكيل يعتمد على إصدار يدعم مخطط الخطافات المستخدم وتفعيل الربط وبدء جلسة جديدة. كشف مجلد الوكيل وحده لا يُعرض كجلسة عمل حية.
- يجب مراجعة الموافقات غير المدعومة أو الكبيرة في الوكيل الأصلي. لا توجد موافقات دائمة للخطافات. Android يدعم موافقات الخطافات المتوافقة؛ موافقات جلسة Hermes المُدارة تبقى في الكمبيوتر.
- Gemini والصوت والرؤية والبحث تحتاج مفاتيح وحصصًا صالحة. اختبارات الخدمات لا تثبت إجابة نموذج حية.
- الهاتف يعرض أسماء الخلفيات والتطبيقات، ومعاينة تغييرات الملفات فيه تعرض المسار وأعداد الأسطر حاليًا. المحادثة نصية.
- Windows غير موقّع بشهادة ناشر، وAPK بتوقيع Debug. يحتاج توزيع الإنتاج وتوقيعه وإعداد التحديثات إلى إعداد مستقل.

## ملفات التوزيع

الملفات النهائية في `release`: `MOHIVX Island 1.2.0.exe` و`MOHIVX Island Setup 1.2.0.exe` و`MOHIVX 1.2.0.apk`. يشمل فحص التغليف مطابقة ملفات خدمات Electron والوسيط والتراخيص وواجهات JavaScript/CSS للمصدر، وفحص تشغيل HTTPS المشفر من أرشيف التطبيق دون فتح نافذة. تُسجل البصمات الرقمية خارج شجرة المصدر أثناء التحقق.
